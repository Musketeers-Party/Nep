# Security Policy

## Supported Versions

Nép is currently under active development. Security updates are provided for the latest maintained version of the project.

As the project evolves, this section will be updated to reflect the versions that receive security fixes.

| Version | Supported |
| ------- | --------- |
| Latest development version | :white_check_mark: |
| Older versions | :x: |

## Reporting a Vulnerability

We take security issues seriously and appreciate responsible disclosure from anyone who helps us identify potential vulnerabilities in Nép.

**Please do not report security vulnerabilities through public GitHub Issues.** Public reports may expose users or the project to unnecessary risk before a fix is available.

To report a vulnerability:

1. Navigate to the repository's **Security** tab.
2. Select **Report a vulnerability** to submit a private vulnerability report, if private reporting is enabled.
3. Include as much relevant information as possible, such as:
   - A clear description of the vulnerability.
   - Steps to reproduce the issue.
   - The potential impact and affected components.
   - Relevant logs, screenshots, or proof-of-concept examples, where safe to share.

If private vulnerability reporting is unavailable, contact the project maintainers through an appropriate private communication channel rather than publishing exploit details publicly.

## Response and Resolution

After receiving a report, the maintainers will:

- Acknowledge the report within **7 calendar days**, where reasonably possible.
- Review and assess the reported issue and its potential impact.
- Provide updates as the investigation progresses.
- Work on a fix or mitigation for accepted vulnerabilities.
- Communicate the resolution and any relevant upgrade or mitigation instructions when appropriate.

Response times may vary depending on the severity and complexity of the issue and the availability of the maintainers.

## Scope

Security reports may include, but are not limited to:

- Unauthorized access to user accounts or data.
- Exposure of sensitive information, credentials, or API keys.
- Authentication and authorization vulnerabilities.
- Insecure handling of location data or location permissions.
- Vulnerabilities in backend APIs or data storage.
- Insecure communication between the mobile application and backend services.
- Input validation issues that could compromise the application or its users.

## Disclosure Guidelines

Please allow the maintainers reasonable time to investigate and address a reported vulnerability before disclosing technical details publicly.

Good-faith security research is appreciated. Do not access, modify, or disclose other users' data, disrupt services, or perform testing beyond what is necessary to demonstrate the reported issue.

Thank you for helping keep Nép and its users safe.
